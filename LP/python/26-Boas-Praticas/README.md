# 26 — Boas práticas, Clean Code e princípios de design

> ⚫ **Profissional**

Código é lido mais vezes do que escrito. Boas práticas existem para tornar mudanças, testes e colaboração menos caros — não para seguir uma religião de regras.

## Fundamentos

- nomes claros e consistentes;
- funções pequenas com responsabilidade definida;
- módulos coesos;
- dados validados na fronteira;
- testes de comportamento;
- documentação onde a intenção não é óbvia;
- formatação e lint automatizados;
- erros tratados com contexto útil.

## PEP 8 e ferramentas

PEP 8 é uma referência de estilo. Use formatter/linter configurado no projeto para evitar discussão repetitiva de espaços e ordem de imports. Ferramenta melhora consistência, mas não substitui nome bom ou desenho claro.
