# Trabalho em equipe e evolução contínua

## Comunicação técnica

Antes de implementar, confirme objetivo, restrições e definição de pronto. Ao reportar problema, descreva ambiente, passos para reproduzir, comportamento esperado, comportamento real e evidências relevantes.

## Pull requests

Uma PR boa é pequena, tem título claro, contexto, testes e instruções de revisão. Não misture refatoração grande com nova funcionalidade sem explicação; isso torna revisão e rollback difíceis.

## Aprender bibliotecas

1. leia o guia de início e a versão suportada;
2. faça um exemplo mínimo;
3. leia API/referência do recurso usado;
4. teste casos de erro;
5. integre gradualmente ao projeto;
6. acompanhe changelog de atualizações relevantes.

## Carreira

Portfólio forte mostra problema, decisão, código legível, testes, README e evolução. Não precisa ser um projeto gigante; projetos pequenos bem acabados demonstram mais do que cópias sem entendimento.
