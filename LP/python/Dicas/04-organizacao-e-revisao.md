# Organizar código e revisar

## Antes de crescer

Comece com uma função clara. Extraia módulo/classe quando há responsabilidade ou mudança independente. Estrutura demais antes de necessidade deixa projeto difícil de navegar.

## Perguntas de revisão

- este nome explica propósito?
- função faz mais de uma coisa?
- entrada externa foi validada?
- erro tem mensagem útil?
- teste cobre regra e limite?
- segredo/arquivo de máquina entrou no commit?
- README explica execução?

Revise o próprio código no dia seguinte; distância ajuda a perceber complexidade escondida.
